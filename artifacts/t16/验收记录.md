## 实际页面检查

默认桌面浏览器及 390×844 视口实际渲染，通过正常页面操作完成：

- 16 人列表与可执行技能详情；编成张飞、关羽、赵云、后羿、嫦娥、华佗六人队。
- 张飞向前换位后，准备页与服务端快照保留相同顺序；出征消耗一次行动力，进行中换位和修炼按钮锁定。
- 首战实际 3 轮、16 次行动；战报显示五虎攻击强化、奔月附加护盾、护盾吸收与治疗，合计气血 673→670。
- 重播、完整交锋、1×/2×、跳过、展开完整战报可用；重播和跳过沿用已保存战报，未发出出征决策请求。
- 刷新恢复同局、同气血与最后战报；返回宗门后可继续，切档可恢复各自出征。
- 单人失败档显示实际全灭、部分收益提示，结算后返回宗门并施加伤势。
- 手机编队两排三人，技能/状态长文案和弹窗可滚动；页面未发现横向溢出。键盘焦点可见，Escape 关闭弹窗并回到入口。

首轮发现编队图片 `cover` 裁掉人物头部，已改为 `contain` 并预留姓名区域；石甲与玉卫初稿轮廓近似，已分别绘制岩甲重锤与高冠玉盾长矛。修改后重新渲染检查，并重跑前端测试和构建。

## 隔离故障检查

另启临时 Vite 验收服务器，代理到同一隔离后端，以服务器中间件模拟；正式代码没有测试开关。

| 场景 | 模拟方式 | 实际结果 |
|---|---|---|
| 等待 | API 延迟 1.8 秒 | 桌面/手机显示载入页及处理中气泡，随后恢复战场 |
| 失败 | API 返回 503 | 桌面/手机显示失败文案与重新尝试按钮，不标为成功 |
| 缺图 | 本地资产返回 404 | 塔背景降为底色，人物用程序轮廓替代，姓名/气血/战报仍可读，操作可用 |
| 减少动态效果 | 临时 HTML 注入将对应 `matchMedia` 返回值设为 true | 直接显示最终状态、重播禁用且有说明，后续词条与战斗决策可继续；未修改操作系统设置 |

## 性能与组合对照

复现命令：`backend/.venv/Scripts/python.exe tools/measure_battles.py`。详细输入、代码指纹、每层结果与原始耗时保存在 [benchmark.json](benchmark.json)。脚本只在内存构造状态，不连接数据库。

- 六套阵容 × 等级 1/3 × 三个固定种子，共 36 次出征。路线和词条固定选择第一项，没有估算胜率。
- 人工高气血 6v6、20 轮：240 次主行动、2136 条效果，五次模拟含序列化中位 177.844ms；仅代表当前 Windows 机器，不包含网络和前端演出。
- 人工战报 2,135,236 B，含固定输入的整档 2,142,640 B；该夹具验证主行动上限，不是所有可能内容的最大字节数证明。实际阵容样本整档峰值 373,027 B。
- 机制队等级 1 的三个固定样本均通关；纯三品队只有一个通关；低品质替换队等级 3 三个样本通关。说明当前样本中机制配合有价值，尚不能证明全局平衡。
- 正式战场无新增位图，复用现有 16 人及塔背景。生产构建 JS 175.63kB（gzip 64.46kB），CSS 60.09kB（gzip 12.99kB）。

本次未穷举全部阵容、成长与词条；人工极限战报仍偏大，后续内容膨胀时应优先减少重复状态载荷并继续测量，当前没有拆存档或增加常驻 tick 服务。
