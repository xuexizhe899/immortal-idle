## 事实来源与保存范围

服务端结算时，在同一次 revision CAS 中发放战利品、释放出征成员、清理 `active_run`，并写入 `GameState.last_run_review`。只保留最近一次结算，下一次结算覆盖；新出发不抹掉上次摘要。旧档缺字段按 `null` 读取，不补发收益。

| 字段 | 来源与含义 | 缺失及上限 |
|---|---|---|
| 模式、到达层/段、总节点、结果 | 本局模式快照与真实结束状态 | 不读取最新配置改写历史 |
| 最终战利品 | 与当次实际入库相同的 `loot` | 材料已按正式结算取整，失败已折算 |
| 末战轮数、承伤、治疗、战前/战后气血 | 最后一场 `BattleSummary` 的我方事实 | 没有末战时不补造 |
| 施加护盾、吸收伤害 | 对我方目标的真实 `shield.amount`、`damage.absorbed` 求和 | 缺事件/我方来源返回 `null`，显示“未记录”，不混计敌方 |
| 本场首位新倒下者 | 按事件顺序查找我方气血由正值变为零的第一人 | 开场已倒下者不计；并列沿事件单位顺序，缺记录不猜 |
| 战后存活敌人 | 最终单位快照中敌方气血大于零者 | 最多 6 个 |
| 三条最高伤害记录 | 逐行动正伤害按金额降序、行动序号升序、目标 ID 升序 | 最多 3 条；含轮数、序号、双方与招式；不是失败原因判定 |

不保存完整逐行动动画、所有历史出征或新的任务状态。摘要数量不随游玩次数增长；只覆盖末战，不能解释成“整次出征首位倒下”。

## 页面与下一步

宗门总览以持久化摘要为准，避免与旧内存结算卡重复。事实先显示，建议单独标为“下次可尝试”；战前/战后气血使用箭头，不误标成生命上限。关键行动可展开，保留原始轮数和行动序号，存活敌人可见。

- 当前有伤员：以当前存档的伤势提示查看疗伤；不把上局低气血当作永久伤势。
- 末战回合耗尽：说明二十轮仍未击败敌人，可以查看输出/破防配合，下次比较轮数与存活人数。
- 其余失败：以倒下顺序与敌人招式为检查入口，不断言“等级不够”或保证某种投入获胜。
- 胜利：确认已完成本次行程，可查看培养/专武作为自选方向。

按钮只导航到已有弟子、炼丹或专武入口；资源、对象、解锁条件和实际消耗仍由原页面及服务端确认。进行中出征显示只读提醒，不绕过原互斥规则。首页在无活动出征且有失败摘要时优先指向复盘，再考虑值守等目标。
