## 3. 撤回的解释与当前证据边界

### 3.1 增伤是否改变击杀顺序，需要行动事件

旧文中临时调整妙算数值的实验没有对应完整输入与战报，撤回据此得出的普遍结论。自动战斗的击杀阈值发生在逐次行动，不一定要少打一整轮；更早击倒尚未行动的敌人也可能减少承伤。当前聚合不足以证明增伤不提供生存收益，更不足以支持新增溢出伤害机制。

### 3.2 条件词条必须有触发源

条件词条是否触发，要核对每名行动者的状态和真实事件。缺少诸葛亮不等于缺少护盾来源；同层数不能证明词条无效。需要单独构造确实无护盾动作的对照，才可以评估缺触发源的情况。

### 3.3 生存类词条的价值取决于"是否已经在掉血"

默认队伍没有治疗动作，不能用它证明治疗溢出或治疗无力。评估恢复构筑需要包含治疗来源，并同时查看我方有效治疗、我方承伤、阵亡与回合；缺少请求治疗量时不推算溢出。

## 4. 限制

1. 核心历史对照是 3 个种子（3、11、19）、6 个场景，其中 B 改变了队伍，C 人工注入道法；不代表全部组合或自然养成路径。
2. 后续策略固定为"取首个"，没有模拟玩家的针对性换位与技能目标选择。
3. 未包含专武、定向丹药与 T18 之后的全部培养上限。
4. 未测二十轮上限的极端局与首领单独对局。
5. 历史文件缺代码指纹与完整战报，不能将其作为当前代码的精确复现证据；新输出另存并记录指纹。

## 5. 后续建议（不在本期）

1. 先补有真实治疗来源、无任何护盾来源的对照，记录实际触发与击杀行动，再决定是否调整候选权重或数值。
2. 将到达层、是否通关、终局状态和过程指标共同呈现，避免单个指标替代收益判断。
3. 当前证据不支持新增溢出转盾等机制；需要新玩法时另行提出具体问题与对照。

实际执行命令为 `backend/.venv/Scripts/python.exe -`，通过 PowerShell here-string 运行以下生成段（之后仅打印 JSON 汇总，不改变数据）；同一段可复现六份当前文件：

```python
import json
import sys
from pathlib import Path
sys.path.insert(0, 'tools')
import compare_affix_choices as compare
for label in ('a-full', 'a-hurt', 'b-shield', 'b-noshield', 'c-plain', 'c-built'):
    original = json.loads(Path(f'artifacts/t21/case-{label}.json').read_text(encoding='utf-8'))
    report = compare.compare(**{key: original[key] for key in (
        'seed', 'step', 'level', 'realm', 'hp_ratio', 'owned', 'party'
    )})
    Path(f'artifacts/t21/review-{label}.json').write_text(
        json.dumps(report, ensure_ascii=False, indent=2) + '\n', encoding='utf-8'
    )
```
