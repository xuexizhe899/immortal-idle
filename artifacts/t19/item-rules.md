## 2. 丹药规则

### 2.1 获取与使用

| 项目 | 方案 |
|---|---|
| 炼制 | 丹方消耗材料，产出 **1 个对应丹药到行囊**，不再立即服用 |
| 使用 | 独立命令：选择 1 名已拥有弟子后使用；每次消耗 1 个 |
| 出征限制 | 有进行中的出征时不可使用；不从战斗中服药 |
| 目标限制 | 目标必须已拥有；疗伤无伤拒绝；破境必须满足 T18 等级门槛/境界上限 |
| 失败 | 目标、限制、库存、revision 任一不通过都不扣物品 |
| 旧库存 | `healing_pill` 作为 `liao_shang_dan` 的兼容别名，使用时优先消耗旧物品；不自动兑换、不补发 |

### 2.2 逐丹效果（建议）

| 丹药 | 目标 | 新效果 | 次数/上限 | 说明 |
|---|---|---|---|---|
| 固元丹 `gu_ti_dan` | 指定弟子 | 永久个人防御 +5% | 每人最多 3 次（+15%） | 不再写全宗门 `state.bonuses` |
| 聚气丹 `ju_qi_dan` | 指定弟子 | 永久个人攻击 +5% | 每人最多 3 次（+15%） | 同上 |
| 回灵丹 `hui_ling_dan` | 指定弟子 | 永久个人修为值守速率 +10% | 每人 1 次 | 只影响该弟子的值守贡献 |
| 养神丹 `yang_shen_dan` | 指定弟子 | 永久个人行动力恢复速率 +15% | 每人 1 次 | 只影响该弟子的值守贡献 |
| 疗伤丹 `liao_shang_dan` | 指定弟子 | 清除全部伤势 | 每次消耗 1 个 | 无伤势时拒绝 |
| 破境丹 `po_jing_dan` | 指定弟子 | 境界 +1 | 受 T18 门槛和最高境界限制 | 不收声望；与突破命令共用规则 |

### 2.3 个人加成与旧全局加成

- 新的个人丹药加成不写 `state.bonuses`；在出发时与等级/境界/永久宗门加成/武器加成一起固化。
- `state.bonuses` 的历史值保留；旧炼丹已获得的全局加成继续生效，不倒推、不重复兑换。
- 个人丹药加成、武器加成、临时战斗状态的叠加上限在规则表中分别标明；本轮不新增随机词条或多层临时增益。

### 2.4 生产类丹药的语义

建议采用“永久个人值守加成、每人每种 1 次”，而不是限时 buff：

- 回灵丹只提高该弟子值守时的修为贡献，不提高全宗门基础速率。
- 养神丹只提高该弟子值守时的行动力恢复贡献。
- 值守结算仍按 `duty_events` 分段：使用前先补算旧速率，再记录新速率；不使用全局 `state.bonuses` 冒充个人效果。
- 备选方案是 8 小时限时个人 buff，需要额外的到期时间、快照和 UI 倒计时；不作为默认。

## 3. 专武规则

### 3.1 归属与装备

- 每名弟子 **1 个专武槽**；武器绑定 `template_id`，只允许对应弟子装备。
- 炼制产出 1 把武器到行囊；装备时从行囊移入 `DiscipleState.equipment`，卸下时移回行囊。
- 同一把唯一武器最多存在 1 把；在行囊或已装备时再次炼制/领取必须被服务端拒绝。
- 不可转移给其他弟子；不新增强化、精炼、随机词条、多装备位、耐久或付费抽取。
- 普通法器不自动转为专武；现有 6 个器方继续作为宗门永久加成，每个器方只能打造一次，UI 需明确标注“宗门加成，非专武”。

### 3.2 获取路径

- 条件：已拥有对应弟子、到达指定塔层、达到指定等级；条件在服务端校验。
- 第一批量产建议：**塔 8 层 + 弟子 3 级**；在器道/专武列表显示“未拥有角色 / 塔层不足 / 等级不足 / 材料不足”的具体原因。
- 器方解锁后可重复查看；炼制消耗材料；不引入付费抽取。

## 4. 数据、接口与可靠性

### 4.1 数据模型

- `GameState.inventory` 继续作为唯一库存：材料、丹药、专武数量都在这里，不建第二套库存真值。
- `DiscipleState.equipment: list[str]` 限制为 0 或 1 个已识别武器；旧档未知 ID 保留展示但不生效、不删除。
- 新增 `DiscipleState.pill_uses: dict[str,int]`（默认空），记录个人丹药使用次数；旧档默认空。
- 新增 `config/weapons/*.json`，包含 id、name、template_id、stats、bonuses、inputs、unlock；接入 `config_loader`、catalog、`validate_config` 和测试。
- 普通 6 个器方保留现有宗门永久加成语义，每个器方只能打造一次；不转换成专武。

### 4.2 命令

| 命令 | 用途 | 关键校验 |
|---|---|---|
| `POST /items/use` | 使用丹药 | 目标、库存、限制、T18 门槛、revision/CAS；失败不扣物品 |
| `GET /weapons` | 专武列表 | 返回已拥有/已装备/解锁条件/材料/不可用原因 |
| `POST /weapons/craft` | 锻造专武 | 拥有角色、塔层、等级、材料、唯一性；失败无消耗 |
| `POST /weapons/equip` | 装备 | 归属模板、库存、单槽；失败无变化 |
| `POST /weapons/unequip` | 卸下 | 已装备、行囊容量/库存一致性 |

- 所有写命令沿用 `prepare_mutation` → 先补算旧区间 → 校验 → 原子提交；revision 冲突返回 409。
- 个人丹药改变值守速率时记录新的 `duty_events`；旧区间不重算，新速率从使用时刻生效。
- 出征中的弟子不可使用丹药/换装；有进行中的出征时不可服用（本轮不开放战斗中服药）。
- 请求结果不确定时只查询最新状态，不重放消耗命令。

### 4.3 旧数据与序列化

- `state.bonuses` 历史值保留；新增字段有安全默认值。
- `healing_pill` 使用别名，优先消耗旧物品；不自动兑换。
- `equipment` 中未知旧 ID 原样保留、不应用、不删除；UI 标注“旧装备未识别”。
- 导出/导入、存档快照、恢复后的个人丹药次数和装备归属必须一致。
- 不追溯猜测历史丹药由谁服用，也不把旧全局加成换算成个人物品。

### 5.2 资产与生图流程

- 16 把专武全部需要 64×64 SVG 图标。
- 生成方式：先用生图生成 16 张单件专武参考图，作为造型、材质和纹样参考；再在 `tools/generate_item_icons.py` 或独立生成器中手绘 SVG。游戏只加载 SVG，不内嵌位图，不把 PNG 自动描摹后冒充本地矢量。
- 生图模型与调用上限已确认：`gpt-image-2.6-sunburst`，总上限 20 次；先生成 4 张代表试稿（刀、矛、药箱、扇）确认风格，再生成其余 12 张，预留 4 次重试。
- 4 张试稿与其余 12 张参考图已全部落盘到 `assets/masters/weapons/`，记录见 `assets/prompts/weapons/trial-01.json`、`batch-02.json` 与 `assets/manifest.json`；生图总调用 16/20 次，未使用重试额度。
- 成功结果立即落盘，网页只引用本地 SVG。
- 不重绘人物；未生成或未确认的插画不能写成已交付。图标必须分别体现刀、矛、药箱、扇、枪、弓、轮、伞、琴、仪、剑、书卷、羽等轮廓，不能只换色。
