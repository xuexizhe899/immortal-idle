## 一、目标与边界

总体判断：引擎（服务端权威经济、确定性重放、加权三选一、真实取舍选路、复盘闭环、测量基线）已是中高配；内容（3 组词条、10 种敌人、3×20 层塔、9 座外宗、3 级设施、事件层空白）仍是首版配。第一矛盾是**目标链断裂**，不是缺系统。本卡只补"通关后的下一环"和"资源心智模型"，不新增系统。

本卡实施范围仅 P0 四件事，且全部是展示与接通，不改战斗、培养、掉落、值守与征讨规则：

1. 单场论道落地后的显示侧接通（论道本体按 P0 v2 确认后实施）。
2. 材料来源总览：缺什么就去打哪里。
3. 收取收益接"现在能做什么"：把挂机数字翻译成决策。
4. 弟子分配总览：值守/驻守/出征三角分配的机会成本可见。

硬边界沿用 AGENTS 与已锁定决策：不新增货币、模式、任务系统、成就奖励、真实时间限时事件、多人、抽卡；服务端独占资源与产出计算；确定性随机；消耗命令带 revision/CAS；不自动补发资源；旧档缺字段按原逻辑运行。史墙类记录只记录、不发奖（T23 边界）。

设计储备不在本卡实施，归入既有卡或触发另开卡，见第八节。词条深度归 T21，战斗画面归 HD-2D 方案阶段 2，避免重复建卡。

## 三、先交付规则，再实施

先产出 `artifacts/t25/goal-chain-rules.md`，经确认再动代码。规则稿按链路组织，不按页面堆功能：

| 链路 | 必须回答 |
|---|---|
| 数据来源 | 矩阵与预览读哪个响应/配置字段？服务端预览不足时，契约增量方案是什么？ |
| 计算定义 | 缺口、每小时边际产出、机会成本说明的口径与取整；前端只做纯展示换算的边界 |
| 缺失行为 | 材料无主动来源、论道未开放、旧档缺字段时显示什么；不填 0、不伪造 |
| 跳转条件 | 跳到哪个现有入口；导航不自动扣资源、不发命令 |
| 保存上限 | 新增本地偏好（如目标设施选择）不写入 `state_json`；无新增存档语义 |
| 验证方式 | 每条链路用隔离测试档或现有响应核对，视觉由用户人工检查 |

## 四、P0 规则要点

### 4.1 单场论道接通

P0 v2 确认后按其 §8 顺序实施；本卡负责论道奖励展示与 4.2/4.3 的接通、验收组织。奖励表、`is_retrial`/`retrial_reward` 快照、独立结算分支均以 P0 v2 为准，不另行发明。

### 4.2 材料来源总览

- 入口放弟子堂或宗门总览次级页签（规则稿二选一），不新增底栏入口。
- 纯展示读 catalog/config 生成 14 种材料 × 来源矩阵：挂机基础、值守专长、外宗驻守、塔掉落、征讨首胜、论道（开放后）。
- 区分"每小时速率"与"一次性奖励"两种口径；无主动来源的材料如实说明现有挂机/值守途径，不制造死锁叙事。
- 不发起请求、不计算扣费；来源 ID 悬空时配置校验应失败。

### 4.3 收取收益接"现在能做什么"

- settle 后前端复用 `held(id)` 缺口逻辑，高亮"可升级设施/可炼配方/可突破弟子"中优先级最高的一项；无可行动缺口时回落到 `currentGoal` 导航。
- 服务端仍负责费用、可升级判断与扣款；高亮只是导航，点击仍走原入口与原命令。
- 离线收取分项（值守/驻守/消伤）沿用现有结算响应，不新增后端统计。

### 4.4 弟子分配总览

- 汇总值守/驻守/出征/空闲四种状态与每人每小时产出预览，复用 `personal_duty_rates` 与驻守预览；现有预览不足以表达边际产出时，先提契约增量方案，不在前端另算一套速率。
- 说明机会成本：把某弟子从驻守改值守会改变哪些产出，用真实预览差值表达，不写死文案结论。
- 不改变离岗/回岗、岗位满不挤走、出征锁定等既有规则；入口位置规则稿定。

## 五、实施落点与顺序

1. 规则稿 `artifacts/t25/goal-chain-rules.md` → 用户确认。
2. 论道（P0 确认后）→ 来源总览 → 收取接通 → 分配总览；每步独立可验收。
3. 纯展示改动不碰契约；确需契约增量时走 Pydantic → OpenAPI → TS，不手改生成产物。
4. 同步直接相关说明：`DESIGN.md` §7、`tasks/README.md`、`frontend/README.md`；不把未验证计划写成完成记录。

## 六、验证与完成标准

按改动范围选择检查：后端业务改动跑相关后端测试；论道以 P0 v2 §6 为准；配置改动跑 `tools/validate_config.py`；涉及随机源跑 `tools/check_rng_usage.py`；数值改动跑 `tools/measure_*` 基线对照并记录。前端相关测试与 `npm run build`；桌面/390px 视觉由用户人工验收，不得因构建成功勾选。

- [ ] 规则稿交付并经确认；确认前不实施。
- [ ] 玩家能回答"缺 X 去哪里"：来源矩阵覆盖 14 种材料，口径区分速率与一次性，无悬空来源。
- [ ] 收取屏能指向一个真实缺口或下一步导航；不自动发命令、不扣资源。
- [ ] 分配总览能说明一名弟子的机会成本；速率与服务端预览一致。
- [ ] 论道若本轮实施，按 P0 v2 §5 两类案例在隔离测试档验证并记录。
- [ ] 储备项未混入本卡：无新增任务、奖励、货币、模式或养成轴。
- [ ] 旧档缺字段、切档、刷新后展示归属正确；本地偏好不写入存档。
