# T16 · 六人出征、技能与羁绊组合

2026-11-12（北京时间）。状态：已实现并完成本轮检查；结果见 [修改汇总](../CHANGELOG-2026-11-12.md)。数值仍需后续试玩打磨。

用户已确认推进技能模块，技能应与羁绊关联、形成多种组合，出征人数上限为六人。项目尚未上线，本期不保留旧出征结构兼容。文中组合与固定种子对照不能视为胜率保证。

## 一、目标与当前差异

目标是让玩家能解释“为什么带这名弟子、这次技能如何帮助队伍获胜”，同时保持自动战斗，主要决策仍发生在组队、选路和词条三选一。

| 项目 | 本期开始前 | 本期实现 |
|---|---|---|
| 出征人数 | `run_engine.start_run` 实际允许 1–5 人，旧 T06 的 3–5 人已不准确 | 1–6 人；六人为上限，不要求满编 |
| 战斗 | 队伍总战力决定胜负与集体扣血 | 服务端逐人自动回合，技能真正生效 |
| 技能 | 32 条资料，catalog 统一标记未实现 | 现有 16 人各有主动与战斗被动，逐项标明实际支持状态 |
| 羁绊 | 四组出征属性加成，一组值守加成 | 出征羁绊强化成员技能，通用技能机制允许跨羁绊组合 |
| 气血 | `tower.start_hp=600` 是独立集体资源，弟子 hp 只参与战力加权 | 新局逐人气血跨层保留，总气血条只展示合计 |
| 敌人 | 节点只有难度数值，`config/enemies` 尚无实体内容 | 配置真实敌方气血、攻击、防御、身法和少量技能 |

六人限制将战斗规模控制在较小范围，但相对当前五人上限不会减少运算。复杂度主要通过固定回合上限、有限效果、禁止递归联动来控制。

## 二、技能如何与羁绊关联

### 术语

- **主动**：轮到弟子行动时，冷却就绪且存在有效目标就自动使用的招式。
- **战斗被动**：角色自身的固定强化或本次行动的条件强化，不依赖点击，不向宗门永久资源反复写入数值。
- **机制配合**：护盾、治疗、降防等实际效果在不同角色之间产生的配合，不要求角色属于某个具名羁绊。
- **人物羁绊**：出发名单满足指定成员数后，本局获得的成员技能强化。
- **联动**：满足条件时，羁绊对当前技能的目标数、效果强度、持续时间或附加效果作一次有限修改。

技能先独立成立，再由羁绊强化。例如任何角色提供的护盾都能支持后羿的护盾条件；嫦娥与后羿同阵时，奔月羁绊可以让月华额外为后羿提供护盾。这样既能凑关系，也能按机制选人。

羁绊规则：

1. 出发时按不同角色模板计数并固化是否激活。战斗中倒下不反复开关羁绊；倒下者不能行动，存活成员仍保留已激活强化。
2. 每条强化绑定明确的技能和效果。技能、羁绊及词条的收益来源分别进入战报，不能把同一条加成重复计算。
3. 条件使用本次行动开始时的状态。例如“攻击已降防目标”不能被该次技能自己刚施加的降防追溯触发。
4. 附加效果属于当前施法，不生成新行动，不再次触发被动或羁绊。没有追击套追击、反击套反击。
5. 六人中不设置固定的羁绊数量要求，也不要求攻、防、辅、炼各占一个名额；原有倾向继续表达值守用途，不作为职业锁定。

### 现有羁绊的改造方向

出征羁绊使用下列技能强化，移除旧的全队属性百分比，避免相同羁绊被计算两次。

| 现有羁绊 | 成员与人数 | 新局技能配合 |
|---|---|---|
| 五虎上将 | 关羽、张飞、赵云，3 人 | 赵云先降防、关羽攻击降防目标；张飞主动施盾时，额外为关羽、赵云施加短时攻击强化 |
| 封神 | 哪吒、杨戬，2 人 | 杨戬降防；哪吒主动攻击已有降防的目标时，可额外命中一名敌人，附加命中在本次施法内结算 |
| 奔月 | 后羿、嫦娥，2 人 | 嫦娥治疗存活友方后，为存活后羿额外施盾；后羿在护盾存在时强化射日 |
| 三分天下 | 诸葛亮、周瑜，2 人 | 八阵图多保护一名队友；赤壁火攻的降防持续时间增加，帮助其他输出角色 |
| 诗圣 | 李白、杜甫，2 人 | 保留现有值守修为加成；两人的战斗技能可与全队配合，本期不为凑满五组而额外附加战斗羁绊 |

羁绊按实际用途展示。出征准备中的“战斗羁绊”不能把诗圣的值守收益列为本局战斗加成；值守面板继续说明诗圣。

### 六人组合示例

| 组合结构 | 六人名单 | 配合与取舍 |
|---|---|---|
| 3＋2＋1 | 关羽、张飞、赵云、后羿、嫦娥、华佗 | 五虎＋奔月＋治疗自由位；华佗可换岳飞或白素贞，交换治疗与护盾能力 |
| 2＋2＋2 | 哪吒、杨戬、后羿、嫦娥、诸葛亮、周瑜 | 三组双人羁绊，检验凑满关系是否压过角色职责；不能预设它必然最强 |
| 2＋2＋1＋1 | 哪吒、杨戬、诸葛亮、周瑜、岳飞、华佗 | 双核心配自由位，偏重持续作战；岳飞换赵云可增加输出和降防 |
| 2＋1＋1＋1＋1 | 后羿、嫦娥、白素贞、岳飞、赵云、华佗 | 一组羁绊配通用护盾、降防和恢复，检验未堆满羁绊的阵容是否有价值 |

这些组合共享成员与效果来源，玩家可以逐个换人。合理目标是不同敌人、伤势和词条下存在不同选择，而非用羁绊数量直接判定胜负。

## 三、一期战斗规则

### 自动回合与目标

- 我方 1–6 人；当前普通、精英与首领遭遇各为 3 人，计算模块双方均支持最多 6 人。
- 每轮开始按身法降序固定行动序列。同身法先我方、后敌方，同阵营再按槽位排序，不依赖字典遍历顺序；先手优势纳入敌人数值对照。身法变化从下一轮生效，不产生额外行动。
- 每名存活单位每轮只有一次主行动。主动可用则施放，否则普攻；治疗没有受伤存活目标、护盾不能产生有效增量时改为普攻，不消耗主动冷却。
- 目标枚举先支持：首个存活敌人、最低气血比例敌人、最低气血比例友方、自身、按槽位取前 N 名存活目标。并列按槽位，选择和结果均由服务端计算。目标在行动开始确定并去重；执行后续效果时已经倒下的目标跳过，不自动改打其他目标。
- 编队顺序决定目标选择的固定优先级。界面提供六个有序名额及简单换位操作；双排仅是演出布局，本期没有前后排距离、站位加成或手动选敌。
- 冷却按自身行动序号计数。例如间隔 3 次自身行动的技能在第 1、4、7 次行动可用；每场开始首次就绪。实际间隔由技能配置决定，不使用现实时间。
- 最多 20 轮；一方全员倒下立即结束。超过上限仍未击败敌人，按本局失败结算，战报明确说明回合耗尽，不能伪造剩余气血被伤害清零。

### 效果与数值

一期限定直接伤害、治疗、护盾、属性增减。暂不加入持续伤害、控制、暴击、闪避、复活、召唤或额外回合；战斗本身不消耗随机数，随机仍用于现有节点与词条流程。

当前伤害公式为 `max(1, floor(攻击 × 技能系数 × 条件伤害倍率 × 100 / (100 + 防御)))`。治疗和护盾按施法者攻击乘配置系数及对应条件倍率计算；最终数值统一向下取整，过量治疗不转盾。系数、防御尺度与冷却是试作参数，不能据此宣称已经平衡。

叠加顺序及限制：

1. 基础气血、攻击、防御使用现有等级/境界成长；伤势按原有每层减攻规则应用一次。基础身法与其加成决定出手顺序，不再同时获得旧总战力公式中的速度权重。
2. 宗门永久加成在出发时固化，原有累计值不截断。新战斗被动只影响相应角色，不把角色效果写入全宗门 `state.bonuses`。
3. 局内词条加在固定参战属性上；临时增益、减益在其后计算。相同来源的同类状态刷新期限、不逐次累加；不同来源按加区相加。
4. 试作中临时属性增减总和限制在 -50% 到 +100%，只限制战斗临时状态，不改写既有永久资产。攻、防、身法不得低于 1。
5. 护盾和临时增减必须配置持续轮数 D≥1，在第 R 轮施加后，于第 R＋D 轮开始清除。来源由施法者、技能及效果条目共同确定，不同施法者不互相覆盖。同来源护盾取“剩余值与新值的较大者”，再按扣除其他来源占用后的容量裁切；新来源只填剩余容量，保留其他已有护盾，总量最多为目标最大气血。实际护盾没有增加时不刷新护盾期限，不能靠重复刷新无限堆盾。
6. 护盾先吸收最终伤害，再扣气血；按施加先后消耗，来源顺序相同时按稳定 ID 排序。伤害不能扣为负数，气血始终位于 0 到最大值之间。
7. 一次技能最多 4 条效果，每条最多 6 个目标。羁绊的条件强化在施法前完成，随后按配置顺序执行效果；额外命中也受相同目标和效果数量上限约束。
8. 常驻属性被动只支持 `always`；条件被动只修正本次行动的伤害、治疗或护盾。条件性 `atk/def/hp/spd` 尚未实现，配置校验和角色工具均拒绝。

### 跨层状态与失败

- 新规则用逐人气血，跨层保留剩余气血；展示的队伍气血为各成员之和，不再另外扣 `start_hp=600`。
- 倒下者本局不能复活；全员倒下或回合耗尽则结束出征。终止原因显式记录，状态推导不能只看合计气血。
- 每场结束清除护盾、临时增减与冷却；下一节点仍从剩余气血开始。治疗只影响本局存活单位，不消除永久伤势，不恢复行动力。
- 气血上限词条按选取前的剩余气血比例调整，向下取整；倒下者保持 0。不得每次读取或重算属性时补满血。
- 节点只结算一次；重复请求、刷新、重播和跳过演出均不能重新获得治疗或奖励。没有等待现实时间回血的局内操作。
- 行动力、失败伤势、待结算战利品、失败部分收益和现有到达层数口径沿用出征流程；奖励参数不在技能试作中顺带调整。战斗回合耗尽算失败，不消除已有待结算战利品。

## 四、角色内容如何落地

保留现有 16 人、立绘、角色 ID、技能 ID 和人物关系。下表描述当前定位，具体系数与完整文案以 `config/skills` 为准。

| 角色 | 主动方向 | 被动/机制配合方向 |

| 关羽 | 单体重击 | 对已有降防的目标强化伤害 |
| 张飞 | 为全体同伴施盾 | 自身常驻防御，支持五虎输出成员 |
| 赵云 | 单体伤害并降防 | 自身身法，优先为队友创造进攻窗口 |

| 杨戬 | 单体伤害并降防 | 强化自身破防能力，为其他输出创造条件 |

| 精卫 | 小范围伤害并降防 | 对已有降防目标强化本次输出，提供低品质机制入口 |

| 杜甫 | 双目标护盾 | 施盾强化，保留低品质保护入口 |

原有 `duty` 预览被动改为战斗被动，逐项实现后由 catalog 标明支持状态。值守仍按现有倾向、品质、境界及诗圣羁绊结算，本期不同时启用额外值守技能。

原 `permanent` 技能明确为“自身常驻”，与炼器提供的“宗门永久加成”分开。角色技能随参战快照固化，不通过重新读配置改动正在进行的出征。

`pill_rate` 尚无真实产出实现。角色工具与配置校验应拒绝将它作为可上线羁绊效果；历史未实现技能资料需要与可执行配置分开处理，不能据此新增丹药挂机产出。

## 五、词条、敌人与平衡

- 保留现有三协同组、三选一和同组权重规则。已有攻击、防御、气血、身法加成改为作用于真实属性；不叠加旧总战力结算。
- 先用现有词条验证“锋锐偏输出、坚守偏保护、奇谋偏先手与配合”；是否替换少量词条为治疗/护盾强化，由试作结果决定，不同时扩充词条数量或改抽取概率。
- 敌人先覆盖普通攻型、防守型和首领三种测试场景，使用现有场景与程序占位演出。正式 20 层必须补齐实际敌人配置；节点 `power` 只能作为难度参考，不能直接同时充当敌人的气血、攻击与胜负条件。
- 同等级、同境界、同伤势、同永久加成和同种子比较阵容，记录通关层数、剩余气血、回合数、有效治疗、护盾吸收和羁绊触发次数。
- 至少比较满羁绊、双羁绊带自由位、单羁绊机制队与纯堆高品质队。检查没有任何一个阵容在全部测试场景占优，也检查低品质功能角色是否存在可解释的替换价值；不提前承诺胜率。
- 六人比五人多一个行动及更多羁绊空间，敌人强度不能原样搬用。保留玩家已获得成长，调整新版本敌人与技能系数，不回收资源、不降低等级或境界。

## 六、服务端模块与契约

战斗作为一个纯计算模块，向出征流程提供小接口：固定战斗输入和本层入场状态进入，战斗结果、离场状态及战报事件返回。内部负责目标、出手、冷却、效果和羁绊修正，不读取数据库、全局时钟或前端状态，不运行任意配置脚本。

规则集中在 `backend/app/domain/battle.py`，`run_engine.py` 负责选路、词条、推进、失败和结算，没有逐技能类或插件框架。

必要输入与输出：

| 输入 | 内容 |
|---|---|
| 参战快照 | 角色顺序、最终基础属性、完整主动/被动定义、已激活羁绊修正；不保留旧战斗引擎 |
| 局内状态 | 各人当前气血、本局已选词条及其固定定义 |
| 敌方遭遇 | 本层敌人属性、顺序和技能，来自本局固定的模式与敌人定义 |

| 输出 | 内容 |
|---|---|
| 战果 | 胜负、终止原因、回合数、各人离场气血；不由模块发放资源 |
| 战报 | 稳定事件序号、行动者、技能、受影响目标、实际伤害/治疗/吸收、状态变化及羁绊来源 |

每次主行动合并为一条事件，目标明细内包含效果结果；每次最多 4×6 条效果目标记录。每场最多 12×20＝240 次主行动，开场被动只做有限初始化，不加入循环事件队列。实际耗时及存档体积在实现后测量，不将该数量上限当作性能实测。

契约先在 Pydantic 定义，再导出 OpenAPI、生成 TypeScript。保留玩家命令的 `revision` 和并发锁；一场战斗与节点奖励累积、RNG 游标、最后战报通过一次 CAS 保存。请求结果不确定时只查最新状态，不自动重发。

## 七、存档与重放

1. 本期直接替换未上线的总战力战斗，不增加 v1/v2 双引擎、旧局转换或迁移分支。已有本地存档不会由实现过程删除或覆盖；旧出征结构不属于本期支持范围，验证使用独立新档。
2. 出发时固化角色数值、技能完整定义、羁绊修正、相关模式/敌人/词条定义。仅存 ID 或版本字符串不足以保证配置改动后重放一致。
3. 每名角色的本局气血独立保存；集体气血字段只导出合计。显式保存本局终止原因，避免回合耗尽后仍可选路。
4. 快照包含出发时的伤势折扣、成长及永久加成，现实时间的自然消伤不会改变本局；读状态不消费 RNG。
5. 中途修改正式配置不改变本局：已选与未来可能抽到的词条、后续敌人和相关数值规则都来自本局固化定义。
6. 只保存最近一场完整战报及前后状态，不把每层动画帧或全部历史战报永久追加到存档。复盘重播读取已保存结果，不再次执行命令；同输入重算用于测试对照。
7. 仍使用整档 JSON、元数据及 revision CAS；本期没有数据库表结构迁移。测试及视觉检查在隔离数据库进行，不能重建或覆盖用户真实存档。

### 程序美术与加载

- 人物复用现有 16 人立绘，复杂场景复用现有塔内背景；本期无需调用生图 API。

- 程序绘图保留在源组件中，使用固定参数与事件序号复现；只承担演出，不生成玩法随机。
- 非首屏人物图片延迟加载；战斗只加载当前场景与参战者，重用几何和动画，检查减少动态效果、渲染失败及跳过操作。
- 后续确有复杂新场景需要生图时，沿用 `gpt-image-2.6-sunburst`，按用户授权单次任务最多 100 张，保留 master 与脱敏记录，运行时只读本地资产。
