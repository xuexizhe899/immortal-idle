# T11 · 前端 UI 与 PixiJS 演出

- 里程碑：M3 ｜ 依赖：T04、T06、T07、T08、T09、T10 ｜ 对应文档：DESIGN.md 第 2、7 节

## 目标
用 Vue 承载全部界面，PixiJS 只负责演出，让玩家能完整操作"收菜 → 编制 → 出征 → 结算"闭环。

## 已锁定决策
1. Vue 3 + Vite 承担**全部 UI**；PixiJS 只做战斗/场景演出，不把 UI 塞进 Canvas
2. **状态权威在服务端**：前端不实现结算、不生成随机、不自行推进时间
3. 类型来自 `src/generated/`（OpenAPI 生成），不手写重复定义
4. 资产按 `asset_id` 从 `public/assets/` 读取；UI 图标用 SVG，不用 AI 生图
5. 多档切换、存档导入导出要可见可用

## 要做的事
1. 局外主界面：资源栏、收菜入口、值守编制（6 位）、弟子列表与详情、炼丹/炼器、解锁进度
2. 出征界面：组队、节点选择、加权三选一、自动战斗演出（PixiJS）、按层数结算展示
3. 伤势与行动力展示：剩余消退时间、可值守不可出征的状态提示
4. 多档管理：新建/切换/复制/删除/导入导出
5. 与后端对接：所有操作走 API，刷新后状态一致；`active_run` 可中断恢复

## 产出物
- `frontend/src/ui/`、`frontend/src/stage/`、`frontend/src/stores/`、页面与交互

## 验收
- [ ] 从零能完成 招弟子 → 值守 → 爬塔 → 受伤 → 炼丹 → 再出征 一整圈
- [ ] 刷新或换浏览器后状态与服务端一致；关浏览器再回可继续上次出征
- [ ] 前端无结算逻辑、无随机生成；改本地系统时间不影响收益
- [ ] 立绘、场景图、SVG 图标正常加载，无 AI 生成图标混入
- [ ] 切档不冻结的表现符合预期：切回时按真实经过时间补算

## 不做
账号登录页、支付、运营后台、实时监控大盘。

## 注意
前端只做"展示 + 发指令"。任何"先在本地算一遍再同步"的写法都会制造第二状态源，直接违反本卡。
