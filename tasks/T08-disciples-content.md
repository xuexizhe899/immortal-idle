# T08 · 弟子与羁绊内容包

- 里程碑：M3 ｜ 依赖：T01、T02 ｜ 对应文档：DESIGN.md 第 7.7 节

## 目标
铺首版弟子内容与羁绊组，让"招聘弟子"和"技能组合"真正可玩，而不是只有数值空壳。

## 已锁定决策
1. 首版 12–20 名弟子，三国 / 神话 / 历史各 4–6 个
2. 差异化：3 档品质 × 4 倾向（攻/防/辅/炼）× 1 专属技能 × 1 被动 × 羁绊组
3. 招聘：声望/材料定向解锁 + 少量随机"云游访贤"事件；爬塔是来源之一，非唯一
4. 重复弟子转化为羁绊经验或通用碎片，**不做付费抽卡**
5. 首版羁绊 3–4 组，按史实与神话关系配置，同阵上场触发

## 要做的事
1. 逐个编写 `config/disciples/*.json`，字段与 T01 schema 对齐，`asset_id` 与 T10 产物一致
2. 配置 `config/bonds/`：羁绊成员、触发条件、效果
3. 解锁规则配置：声望/材料消耗、解锁来源（爬塔、远征、入侵、事件）
4. 招聘与重复转化接口；云游访贤事件接入随机系统（走 T05 的种子）
5. 每名弟子明确其定位：出征价值与值守价值至少占一项，避免纯图鉴角色

## 产出物
- 弟子配置 12–20 份、羁绊配置、招聘接口与配置校验通过记录

## 验收
- [ ] 全部配置通过 T01 校验，无悬空引用
- [ ] 每名弟子技能、被动、倾向、品质、羁绊字段完整
- [ ] 至少 3 组羁绊可在出征中实际触发并生效
- [ ] 招聘不依赖任何付费或随机卡池；重复弟子有明确去向
- [ ] 12–20 名弟子在值守或出征上都有用途

## 不做
新增弟子立绘（T10）、后续批次扩充、跨档图鉴与成就。

## 注意
追加弟子 = 加一个 JSON + 一组图，**不需要改引擎代码**；若发现要改代码，说明配置抽象不够，先回到 T01。
