# T22 · 问道塔选路与单局节奏

2026-11-14（北京时间）。状态：代码与相关自动检查完成；人工点击、时长与视觉验收待执行。实际规则见 `artifacts/t22/route-and-pacing.md`，72 案例与两组真实状态证据见 `artifacts/t22/balance-report.md`。

## 一、目标与任务边界

用户已同意深化问道塔选路与单局节奏。目标是让玩家依据当前阵容、剩余气血、已有词条和眼前威胁作出取舍，并减少不产生决策价值的重复点击。

本期保持问道塔 20 层、第 20 层首领、我方最多六人、战斗最多 20 轮及现有资源体系。不增加角色或关卡数量，不开放远征、入侵、新模式、世界地图或新的资源货币。后续阶段安排前端美术优化，本期只实现理解和操作选路所必需的界面，不顺带重做全站或批量生图。

## 三、已授权方向与待定细则

已授权的方向：消除等价假选择、展示真实可见的遭遇和奖励、让风险与收益有取舍、改善整局节奏。可在此范围内自主核对、设计和实现，不为每个按钮、字段或例行实现选择反复请求授权。

恢复、整备、机缘是候选解决方式，不要求三类全部加入，也不表示其具体效果和数值已经确认。执行前先形成最小规则方案；涉及新增既定玩法、数值、消耗或存档/契约语义的变化，统一说明原因、影响和建议，在授权边界内落地，不将提案悄悄写成正式规则。

| 待定事项 | 设计时必须回答 |
|---|---|
| 恢复 | 是否必要；恢复谁、按什么基数、上限多少；每局次数、出现条件与代价；是否仅影响本局气血。 |
| 整备 | 整备具体改变什么，如何形成现有队伍/词条的取舍；没有可解释收益时不保留空壳节点。 |
| 机缘 | 展示哪些已知收益与风险；随机结果的定义、生成时点和可见范围；不以含糊文案隐藏实际扣费。 |
| 层数与节拍 | 非战斗选择是否占一层或附属于层间；20 层和首领位置不变，总战斗数、词条次数与奖励机会有何差异。 |
| 次数与机会成本 | 有限机会还是消耗现有材料/资源；放弃战斗奖励是否就是代价；不得同时隐去多个代价或新增货币。 |
| 路线候选 | 每次提供几个有实质差别的选项；若当前只能提供一个有效方案，如何诚实显示，避免伪造第二条路线。 |
| 操作精简 | 哪些确认可合并，哪些必须由玩家明确选择；不以自动选词条/路线替代有效决策。 |

“单局约 3–5 分钟”仅为待验证的体验目标，不是已确认时限，不通过强制倒计时、删掉决策或假造耗时达成；长思考和完整战报播放也不能被误算成系统卡顿。

## 四、先交付方案，再实现

先产出 `artifacts/t22/route-and-pacing.md`，附节点表和至少两组真实状态的选择示例，再进入代码实现。方案至少包含：

1. T20/T21 后当前流程、等价候选出现情况、风险回报与重复点击问题，附输入和实际观察。
2. 本期保留/调整/新增的最小节点清单。每项写明节点身份、出现阶段/次数、可见信息、触发条件、代价、结果、是否占层、是否给词条与奖励、下一状态及失败分支。
3. 完整 20 层节拍表，明确普通压力、取舍机会与首领准备之间的关系；不是再铺一张更大的地图。
4. 当前资源与奖励总量的新旧对照。恢复或机缘不能既额外发奖励又无机会成本，形成单一路线始终最优。
5. 两个状态下路径偏好不同的因果解释，以及预计如何从真实战报和收益中验证；“改了推荐文案”不算行为变化。
6. 节点存储、RNG 消费、旧局处理、接口变化与操作次数/时长测量方式；明确已确认项和仍待确认项。

示例仅说明设计目标：同一对可见路线中，气血充足且有能力处理当前精英威胁的队伍，可以承担风险争取明确奖励；核心存活但气血不足的队伍，可能选择有限恢复并放弃该次收益。**恢复存在、数值、出现次数和代价尚未据此锁定**，最终以方案和授权为准。若仅靠现有普通/精英差异即可成立，应优先采用更小方案。

## 五、真实信息与服务端确定性

- 页面展示本次已经生成、允许玩家知道的真实编成、关键威胁、收益和代价。保留未知项的真实不确定性，不伪造胜率、预计伤害或保证通关。
- 仅展示当前决策需要的信息，不预读尚未生成的后续路线来给出全知最优答案；敌人资料说明也不能代替本节点实际编成。
- 节点身份及本次候选由服务端生成并保存；进入节点使用同一份固定遭遇/规则，不能点击后重新抽出另一组敌人。ID、位置和候选索引的含义在方案中明确。
- 新局固化模式、敌人、词条及新增节点所需完整定义。修改正式配置、切页或自然消伤不得改变本局已固化内容。整备若允许改变局内状态，应显式更新对应局内字段，不回写角色永久层或隐式修改出发快照。
- 随机只用本局 `run_seed`/`rng_cursor`；先明确候选生成、机缘结果与后续路线各自的消费时点和顺序。读取、预览、刷新、重播、失败重查不消费 RNG，不提供免费重抽。
- 消费命令复用当前 revision、并发锁、旧区间补算与一次 CAS 保存。节点结果、消耗、次数、奖励、RNG 游标和后续状态同时落档；结果不确定只查询，不自动重发。

## 六、恢复、奖励与中断边界

启用非战斗节点前，必须在方案和实现附近明确以下规则：

- 恢复默认只作用于存活成员的本局气血，不复活倒下者、不清永久伤势、不恢复行动力；任何不同方案都属于需要说明影响的新规则。
- 恢复量由服务端计算，气血不超过当前局内上限；满血、无有效目标、次数耗尽时如何显示与处理必须明确，不能扣费后无效果。
- 节点没有靠现实等待自动回血的循环；刷新、往返宗门和重复请求不能再次恢复或再次领奖。
- 明确非战斗节点是否计入到达层数、失败层数奖励和每层词条次数，避免用无风险节点重复刷奖励、记录或突破条件。
- 收益沿用本局待结算流程；不把机缘所得提前入永久行囊后再在结算重复发放。资源消耗若发生在局外，说明失败后是否返还，不能只靠前端临时扣数。
- 普通失败、全员倒下、回合耗尽与最终清关继续使用明确终止状态；非战斗节点不能把失败局重新带回可选路状态。
- 关闭页面或返回宗门仍保留进度；不自动覆盖旧局。若新节点结构无法安全恢复既有出征，应先明确旧局完成/保留策略及 schema 处理，不将 T16 的历史兼容例外扩大为删除数据授权。
