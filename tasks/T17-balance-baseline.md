# T17 · 战斗规则与平衡基线

2026-11-12（北京时间）。状态：规则账本、T16 复跑、T17 扩展样本与目标建议已完成；未修改玩法数值，具体调整留待 T18–T20 确认。

## 一、目标与授权边界

用户已确认先建立 T17 规则与平衡基线。以当前 T16 六人自动战斗为起点，回答“同等投入下，各类阵容在什么情况下有价值”，为 T18 培养、T19 丹药与专武、T20 敌人优化提供可重复的对照。

本期先建立规则账本、样本和目标，不直接批量调整技能、成长费用、奖励或敌人数值。对照发现的问题应形成具体调整建议；后续确需改既定数值时按授权范围执行。固定种子结果是样本，不是胜率结论。

## 二、开始前阅读与现状

- 阅读 `AGENTS.md`、`ARCHITECTURE.md`、`DESIGN.md`、`tasks/T16-skills-and-bonds.md`。
- 阅读 `backend/app/domain/battle.py`、`run_engine.py`、`progression.py`、`recruit.py`、`duty.py` 和对应配置。
- 复用 `tools/measure_battles.py` 与 `artifacts/t16/benchmark.json`。T16 已有六套阵容、等级 1/3、三个种子的 36 次对照；不复制成“本轮已验证”。
- 核对文档差异：`DESIGN.md` 尚有总战力定胜负、旧出征补快照等历史段落；现行规则以 T16 和实际实现为准。只修正本期直接涉及的冲突，不重写整份设计。

## 三、规则账本

产出 `artifacts/t17/rules.md`，逐项标记“当前实现、配置/代码来源、已知限制、建议目标”：

1. 基础属性、等级和境界成长、伤势折扣、宗门永久加成、局内词条与临时效果的计算次序及取整位置。
2. 目标选择、同速顺序、冷却、状态到期、护盾容量、治疗溢出、倒下与 20 轮终止。
3. 技能与羁绊触发条件；不能用同一招刚产生的状态追溯触发行动开始条件。
4. 修为、灵石、声望、材料、行动力的来源和主要消耗；培养和值守的关联。
5. 逐人气血跨层保留、节点奖励、失败部分收益、伤势与结算口径。

账本只描述可定位的事实；文档、配置和实现不一致时写明差异。

## 四、可复现样本矩阵

- 阵容至少保留：满羁绊、双羁绊带自由位、单羁绊机制队、纯高品质队，以及同核心的低品质功能位替换对照。沿用 T16 的稳定角色 ID 与槽位顺序。
- 先复跑 T16 原矩阵建立可比基线，再增加当前可达的早期、中期、后期培养档位。档位由实际费用与资源收入推导，不随意称为“第一天/第七天”。
- 同组固定等级、境界、伤势、永久加成、初始资源、种子、阵容顺序及选路/选词条策略；改变一个因素时单列对照。
- 固定策略至少保留 T16 的首项策略；补充有规则定义的机制策略，避免所有结论来自“永远选第一个”。不得使用预知未来节点的策略冒充玩家选择。
- 区分单场普通/保护/首领遭遇和完整 20 层出征。T17 不新增敌人种类。
- 记录输入摘要/哈希、版本、命令、环境、种子与决策序列。培养和值守测量显式传入时间，不读写真实存档，不依赖现实等待。
- 输出表包含：完成层数与终止原因、剩余气血/存活人数、回合数、实际伤害、有效治疗/溢出、护盾施加/吸收、具名羁绊触发次数、培养投入。指标定义和统计范围写入结果说明；未能统计的指标明确留空，不能填零冒充无效果。

## 五、目标与问题清单

产出 `artifacts/t17/balance-report.md`：

- 列出当前过强/过弱样本、回合耗尽场景、无效治疗/护盾和低品质替换表现，并附对应输入。
- 建议早、中、后期目标层段、每场回合区间、培养投入与提升幅度；数值注明为待确认目标，不先写成正式配置。
- 对“某阵容全面占优”限定为本次样本集；分析技能机制、成本、先手或敌人单一性带来的原因。
- 将建议归入 T18 培养、T19 个体物品、T20 敌人，保留变更前基线，避免各期互相覆盖结论。
- 如果当前公式确有缺陷，单列复现与修复建议，不将玩法改动藏在测量工具里。

## 六、实施位置与顺序
