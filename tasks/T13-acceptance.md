# T13 · 首版验收

- 里程碑：M5 ｜ 依赖：T11、T12 ｜ 对应文档：DESIGN.md 第 11 节

## 目标
用可判定的标准宣告首版完成，避免"尽可能完善"导致项目没有终点。

## 验收清单（9 条，逐条留证据）

- [ ] **数据不丢**：改本地系统时间不刷收益；服务端时钟回拨有 clamp 与告警；强杀进程重启不丢档
- [ ] **能回滚**：Alembic 可升可降；`schema_version` 老档可迁移；镜像可切回旧 tag
- [ ] **可重放**：同一 `run_seed` 结果完全一致；值守事件流分段补算可复算
- [ ] **可观测**：结构化日志 + 请求追踪 + 全局异常，异常可定位到 slot 与时间段
- [ ] **可重建**：空服务器凭仓库 + 一份备份还原到可玩状态，且已演练
- [ ] **测试**：pytest 覆盖数值公式（含 property-based）、离线收益、种子、并发 CAS；CI 提交即跑
- [ ] **配置完整性**：CI 校验所有引用 ID 无悬空，资产白名单已移除
- [ ] **备份**：定时 `.backup` → 打包 → 留存，且恢复成功过一次
- [ ] **可玩闭环**：从零跑通 招弟子 → 值守 → 爬塔 → 受伤 → 炼丹 → 再出征

## 执行方式
1. 每条验收写清操作步骤、预期结果、实际结果与证据（日志/截图/测试输出）
2. 不通过的项回到对应任务卡修复，不在验收卡上临时改规则
3. 全部通过后打 tag，标记首版完成

## 首版明确不做（避免验收时被当成缺陷）
多用户与登录、支付、远征/入侵实际内容、100 层全量、跨档图鉴与成就、重放调试 UI、Prometheus 监控。

## 通过后的下一步（另开任务卡，不属于首版）
1. 扩爬塔至 100 层 / 5 段
2. 铺远征与入侵者内容（只加配置，不改引擎）
3. 词条池扩到 40–60 条 / 6–8 组，丹方器方各 12–20
4. 弟子批次扩充（加 JSON + 生图，不改代码）
5. 若触发拆行条件（弟子 >1000 或 `state_json` >5MB），再做存储拆分迁移

## 注意
验收是首版的**终点**。任何"顺手再加一个系统"的冲动都应移到下一版，而不是扩大首版范围。
