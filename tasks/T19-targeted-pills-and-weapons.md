# T19 · 丹药指向性使用与专属武器获取

2026-11-12（北京时间）。状态：规则、后端、契约、前端、16 把专武 SVG 与 16 张参考图已完成；4 张试稿已获用户确认，其余 12 张按同一风格生成，生图总调用 16/20 次，未使用重试额度。

## 一、目标与现状差异

用户确认：丹药支持指向性使用，弟子能够获取专属武器；生图可作为资产制作手段。

当前 `craft.py` 将大部分丹药/法器直接累加到 `state.bonuses`；疗伤和破境才指定弟子。`DiscipleState.equipment` 虽然存在，但没有完整物品获取、归属、装备与加成流程，不能视为专武系统已实现。遗留疗伤入口使用 `healing_pill`，正式配方 ID 是 `liao_shang_dan`，必须明确兼容映射。

本期目标是建立“获得物品 → 查看用途 → 指定弟子使用/装备 → 服务端生效”的闭环，避免所有物品最终变成无差别的宗门永久加成。

## 二、规则提案与确认点

执行前产出 `artifacts/t19/item-rules.md`，将以下建议定成明确规则后实施：

| 事项 | 建议基线 | 必须明确的细节 |
|---|---|---|
| 丹药获取 | 炼制先入行囊，使用为独立命令 | 每次产量、配方成本、数量上限与旧立即生效入口处理 |
| 目标 | 选择一名已拥有弟子后使用 | 出征锁定、疗伤无伤拒绝、境界上限、是否允许值守中使用 |
| 效果 | 疗伤、培养、个人属性分别定义 | 每种现有丹药的目标、真实效果、次数/增益上限与持续性 |
| 生产类丹药 | 单列语义方案 | 回灵丹/养神丹当前影响宗门产出，不能把全局速率字段直接塞给个人并声称生效 |
| 专武归属 | 每名弟子一个专武槽，武器绑定明确模板 | 绑定时机、替换/卸下、是否可重复获取及重复后的处理 |
| 专武能力 | 有辨识度的基础属性，必要时一条有限技能强化 | 获得前后预览、上限、叠加顺序、战报来源；不新增递归追击 |
| 获取途径 | 可追踪的角色目标解锁器方，再消耗已有材料锻造 | 每把武器的目标、材料、可重复性；不引入付费抽取 |

专武内容先制作完整 16 人对应表，再确定首批交付名单；建议用输出、护盾、治疗等不同定位做代表闭环，未交付角色不能显示可获取承诺。专武不自动带出强化、精炼、随机词条、多装备位或耐久系统。

现有普通法器是否继续保留宗门加成，须在规则表中写明；不默认把所有旧器方转成专武，也不追溯猜测历史丹药由谁服用。

## 三、数据与可靠性

- 保持整档 JSON 与 CAS。区分物品定义、库存数量、弟子个人成长和武器归属；先评估现有 `inventory`、`equipment` 字段是否语义足够，不建立双重库存真值。
- `state.bonuses` 历史值保留，不在读档时自动重复兑换成药品或专武。新增字段有安全默认值，必要时使用显式可重复验证的 schema 转换，覆盖导入导出和快照恢复。
- 炼制、服用、领取、装备分别为有 revision 的命令，先补算旧区间再原子保存。先校验目标、限制和效果可用性，再扣材料/物品；失败无消耗。
- 重复领取同一唯一专武必须被服务端拒绝或按确认规则处理；前端禁用按钮不能代替校验。
- 请求结果不确定只查询。普通 CAS 防止同一旧 revision 重复扣费；若设计领取标记，应持久化，不能只放组件状态。
- 个人丹药加成、装备属性及技能强化在出发时完整固化；换药品配置或武器定义不能改变进行中的出征。当前不开放战斗中服药。
- 丹药改变值守速率时遵循分段补算；个人治疗不自动清除全队伤势，也不恢复局内倒下角色。

## 四、实现落点

- 阅读 `AGENTS.md`、`ARCHITECTURE.md`、`ART_DIRECTION.md` 和 T17/T18 产物。
- 配置：现有 `config/recipes/`；仅在需要独立物品/武器定义时新增相应配置目录，并接入 `config_loader.py`、catalog、`tools/validate_config.py`，明确 ID 引用关系。
- 规则：`domain/craft.py`、`progression.py`、`run_engine.py`；物品使用/武器归属逻辑具有独立职责时新增 `domain/items.py`，不把网络或数据库塞进领域模块。
- 模型/接口：`models/save.py`、`models/api.py`、`api/craft.py`、`api/disciples.py`；新增物品命令路由按现有编排方式接入，不调用另一路由函数。
- 前端：`views/CraftPanel.vue`、`CodexPanel.vue`、store/API；按需要新增 `components/game/DiscipleEquipment.vue`。`presentation/assetPaths.ts` 统一解析资产。
- 玩家能看到库存、适用对象、服用结果、不可用原因、专武来源与未满足条件。明确区分“已解锁器方、材料足够、已拥有、已装备”。

## 五、美术与生图

- 丹药与武器图标优先扩展 `tools/generate_item_icons.py` 或其他可复现程序绘图；专武通过轮廓、材质与标志物区分，不只换色。
- 可为专武制作复杂展示插画，优先复用人物立绘，不默认重绘 16 人。插画与可装备物品定义分开，图片不能承担规则。
- 生图前列模型、实际调用上限、代表试稿和正式名单；建议沿用 `gpt-image-2.6-sunburst`，但本卡不自动授予历史额度。用户已允许使用生图，具体预算明确后在范围内自主执行。
- 遵循 `ART_DIRECTION.md`：试稿先由用户确认，成功立即落盘，保留 master、prompt 和脱敏记录，网页只读本地成品。现有脚本不支持参考图输入，不能声称已锁定身份。
