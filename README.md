# 修仙放置 x 休闲肉鸽

自用、非盈利的单机多档放置 roguelite。玩法决策见 [DESIGN.md](DESIGN.md)，分层和目录规范见 [ARCHITECTURE.md](ARCHITECTURE.md)，生图风格与验收见 [ART_DIRECTION.md](ART_DIRECTION.md)，任务拆分见 `tasks/`。

## 技术栈

- 前端：Vue 3 + TypeScript + Vite + Pinia；主城使用 Three.js HD-2D，战斗演出仍使用 Vue / SVG / CSS，PixiJS 保留为可选演出依赖
- 后端：Python 3.11 + FastAPI + SQLAlchemy 2.0 async + Pydantic v2
- 存储：SQLite + aiosqlite（WAL），整档 `state_json` + `revision` CAS
- 部署规划：Docker Compose（app + Caddy）；部署文件与镜像流水线尚未落地

## 目录

```
config/     静态内容、技能与羁绊、建筑入口元数据、风格约定
backend/    FastAPI 应用、领域逻辑、仓储、测试
frontend/   Vue 3 界面、Three.js HD-2D 主城、SVG 战斗演出、本地运行资产
assets/     素材来源、master、提示与生成记录
tools/      契约辅助、配置校验、资产与内容脚本、离线测量
artifacts/  任务草稿、截图、测量与验收证据
docs/       方案与审查记录
tasks/      任务卡与验收清单
```

逐级目录职责见 [后端目录说明](backend/README.md) 和 [前端目录说明](frontend/README.md)。后续添加角色或素材时，可复用 [新增弟子指令](artifacts/art-foundation/ADD_DISCIPLE.md) 与 [新增敌人图片指令](artifacts/art-foundation/ADD_ENEMY.md)。

## 本地启动

后端（首次）：

```bash
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000
```

前端（首次）：

```bash
cd frontend
npm install
npm run dev
```

**首次启动前端前必须先生成一次接口类型**，否则 `src/generated/` 为空：

```powershell
cd backend
.venv/Scripts/python.exe scripts/export_openapi.py
cd ../frontend
npm run gen:api
```

## 常用命令

| 目的 | 命令 |
|---|---|
| 重新生成接口类型 | `bash tools/gen_types.sh` |
| 数据库迁移 | `cd backend && .venv/Scripts/python.exe -m alembic upgrade head` |
| 处理立绘资产 | `backend/.venv/Scripts/python.exe tools/normalize_assets.py` |
| 校验配置引用 | `python tools/validate_config.py` |
| 后端测试 | `cd backend && .venv/Scripts/python.exe -m pytest -q` |
| 前端构建 | `cd frontend && npm run build` |

`backend/openapi.json` 与 `frontend/src/generated/` 都是构建产物，已被 gitignore，不要手改。

## 道具图标

丹药、法器与材料图标由本地脚本绘制，不走生图 API：

```powershell
backend\.venv\Scripts\python.exe tools\generate_item_icons.py
```

开发时可用 `--only qing_feng_jian` 单独更新图标；已有完整输出目录的清单会保留其余道具，新的预览目录只登记实际生成的文件。

输出 `frontend/public/assets/items/<id>.svg` 和清单 `index.json`；总览页在 Vite 启动后访问 `/item-icons.html`。新增道具时，先在 `config/recipes` 或 `config/materials` 添加配置，再在 `tools/generate_item_icons.py` 的 `ART` 中补同名绘图函数，并同步 `frontend/src/presentation/assetPaths.ts` 的 ID 列表。重复运行只按内容更新本脚本负责的文件，不清空资产目录。

## 约束

- 本机不装游戏引擎、不装 Docker Desktop、不装本地生图环境
- Python 依赖只装在项目内 `backend/.venv`，不污染系统环境与其他 venv
- 密钥只放本地 `.env`，不进仓库

## 主城与玩法打磨

主城以 Three.js 的立体地形、七座程序建筑和二维人物立牌组成 HD-2D 场景，分别承载宗门总览、弟子/招贤、值守、爬塔、炼丹、炼器和远行。固定斜俯视镜头支持拖动、缩放和回到默认视野；晨昼暮夜随本地时间改变光照，也可在“天色”入口预览，不影响服务端收益。存档管理仍在主殿内，进行中的出征可返回宗门查看，再继续原进度。

首页采用一屏主城与底部固定功能栏，提供宗门、弟子、值守、炼丹、炼器、远行、问道入口，与建筑打开相同面板。问道和远行入口按真实出征状态显示“继续出征”或“待结算”；当前目标以可点击浮签显示，右下可收取收益；收益与最近出征明细在宗门总览查看，阵容在弟子与出征准备中调整。手机可在场景区域单指拖动、双指缩放，底栏始终可达；底栏图标由本地 SVG 绘制。场景只投影真实弟子状态，出征或驻守者不同时出现在本宗，值守者显示在演武场附近；画面失败时仍可通过底栏打理宗门。

场景获得焦点后可用方向键平移、加减键缩放、`Home` 复位，也可使用画面内的视野按钮。“柔景”默认关闭，勾选后开启轻景深；人物轻动作遵循系统的减少动态效果偏好。

本轮迁移覆盖主城，战斗舞台继续播放原有 Vue / SVG / CSS 真实战报；桌面与 390px 的画风、遮挡、手势及性能由用户人工验收。方案和源码参考见 [HD-2D 迁移记录](docs/plans/2026-11-17-hd2d-migration.md)。

T16 已将原型总战力判定升级为 1–6 人自动战斗：逐人气血跨层保留，主动、被动和羁绊由服务端执行，前端只播放真实战报。出发时固化角色、技能、羁绊、敌人、模式、装备与词条定义，刷新与自然消伤不会改变本局输入。当前保留已开始且结构可识别的旧十二段远征与路线快照，旧局不追加新装备掉落的随机消耗；不自动删除本地数据，开发与验收请使用独立测试档。T16 修改与检查结果见 [修改汇总](CHANGELOG-2026-11-12.md)，此前主城修改见 `CHANGELOG-2026-11-11.md`。

T20 在现有自动回合战斗上扩展敌人：问道塔 20 层分 5 段，普通、精英与首领共用既有技能和目标规则；新增赤炉刀卫、竹隐剑客、霜羽鹤灵、青藤木魈、铜角镇兽与引魂灯使，分别承担破防、开场速攻、治疗、群体减伤、重甲护盾与削攻。第 20 层由问道真灵与护卫组成。层段编成与数值对照见 [敌人设计](artifacts/t20/enemy-design.md) 与 [平衡报告](artifacts/t20/balance-report.md)。

规则与验收清单见 [T16 六人出征、技能与羁绊组合](tasks/T16-skills-and-bonds.md)。技能通过伤害、降防、治疗和护盾形成跨角色配合；五虎、封神、奔月、三分天下强化特定成员技能，诗圣继续用于值守。战斗最多 20 轮，路线、道法与新局装备掉落使用服务端确定性随机源，洗练使用独立保存的游标；战报重播与跳过演出都不重新结算。

远行码头现进入地区大地图：云岚下界与青冥灵域各有三个片区，宗门占据固定位置，每个已开放地区随主殿等级开放3/6/9座，仍受片区进度限制。宗门征讨每次消耗2点行动力，带3–6名弟子，每场选择3人进行最多三轮擂台；守备归零后挑战宗主。攻克后领取一次奖励，可派最多3名弟子驻守获取特色材料，也可消耗2点行动力反复进行3v1宗主论道，胜利领取固定奖励、失败零奖励，不重复首胜。

每片区提供两处六段秘境、守关与关键入侵。秘境用于反复刷取资源和个人装备；普通迎击按时间积攒有限敌情，由玩家主动接战，不接战不会扣资源或造成伤势。正式迎击不消耗行动力，胜利后波次难度递增；守关、关键入侵与普通迎击支持无奖励、无新增伤势的演练。最终关键入侵首胜获得升仙令，可开放下一地图图层，保留弟子、装备、资源、驻守与旧区记录；问道塔每地区分别记录三阶、每阶20层的进度。

宗门主殿管理主殿、炼器阁、炼丹房、问道塔和演武场三级设施。普通装备改为武器、盔甲、靴子、戒指四个个人槽位，轻随机副属性分三档；炼器阁提供强化、洗练、锁定与熔炼，普通器方不再增加宗门公共属性，专武保留锻造和逐级提升。熔炼获得本体精粹，并按每种可返累计投入的80%向下取整返还，洗练费不返。弟子堂承载招募与个人培养，每名弟子另有生产专长；挂机产出炼器精粹，主动刷取可加快培养。炼丹支持数量、最大可炼和品级，出征整备支持库存优先、缺额补炼的一键疗伤；出发自动离岗，结束按岗位空位恢复。配方、成本和产量见[经营数值基线](docs/sect-economy-baseline.md)。

点击弟子卡片会弹出独立详情，可切换概览、培养、装备和道法栏目。顶部左右按钮按当前筛选结果循环切换弟子，切换时保留当前栏目并回到详情顶部；也可用键盘左右键切换，输入框和选择框保留原有按键行为。关闭详情会回到原列表位置，Escape只关闭最上层弹窗。主城点选弟子直接打开其详情，招贤列表的“前往培养”直接进入对应培养栏目。

宗门主殿按总览、设施升级、挂机收益、出征复盘、材料来源和存档管理分栏，切换栏目回到面板顶部。问道塔与共用路线历练页的下一步入口置于战场上方，路线与待领悟道法通过弹窗选择；演出结束后自动提示当前选择，手动关闭后可从入口重新打开，同一次选择不会因刷新状态或重播战斗反复弹出。战利品、战斗羁绊和已悟道法集中在战场下方原路线区域，以页签切换查看。

山河地图点击据点弹出情报与整备，宗门节点直接查看对应宗门的驻守或征讨；敌情和飞升各有独立入口。地图在局部视口内滚动，小屏横向查看其他片区，关闭详情保留当前图层与选点。值守分为安排弟子、当前岗位、每时产出和分配预览；炼丹、炼器按用途分栏，配方、装备、专武与弟子换装按需弹出详情，避免列表和所有操作接成长页。宗门擂台的上阵、交锋、撤回入口位于战场上方，结束后结算同样前置；问道整备的羁绊默认折叠。材料来源先查找材料再展开单项，存档的新建与导入入口置于列表前。全页面代码检查范围及本次验证记录见[页面交互检查](docs/reviews/2026-11-19-page-interaction-audit.md)，实际桌面与手机显示效果由用户人工验收。

本轮代码已接入个人装备与地区推进循环，32个隔离新档的首轮测量及二区有限探针已完成；不同参与强度的成长结果与限制见[成长模拟报告](docs/reviews/2026-11-19-progression-simulation.md)。长期平衡、其他阵容与人工体验仍待验收；规则边界与本轮检查证据见[实现审查记录](docs/reviews/2026-11-19-gameplay-progression-implementation.md)，尚未部署。

## 程序美术与加载

人物与敌人使用本地 PNG 立绘/形象；主城地形、建筑体块与像素纹理在 `frontend/src/rendering/hd2d/` 程序生成，人物复用透明立牌。原主城整图保留为构图与配色参考；战斗继续使用本地背景，技能特效、护盾与状态提示用 SVG 与 CSS 在运行时绘制。敌人缺图时回退到程序轮廓，不调用运行时生图接口。

主城按当前存档加载最多 16 名常驻弟子的图片，优先显示值守者；战场只加载参战图片，非首屏人物列表延迟加载。现有 16 张主用立绘、10 种问道塔敌人形象，以及外宗专用的 13 名弟子和 3 位宗主立绘。外宗按剑修、御守、丹修复用各流派人物，宗主拥有独立图片；战前预览与战报均使用服务端图片键。已有宗门自动替换旧塔敌图片，进行中的征讨和历史战报保留原快照，下一次出发使用新图。[外宗人物审阅页](artifacts/sect-conquest/review.html)提供全套图片、原图和小尺寸对照。
