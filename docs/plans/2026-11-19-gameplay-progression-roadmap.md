# 后续玩法与开发路线：个人装备、地区地图、入侵与飞升

日期：2026-11-19（北京时间）。状态：P1–P4 的首版功能、相关检查与 32 个隔离新档的首轮测量已完成；尚未部署，视觉与人工体验待确认。本文保留访谈与开工前基线，实际实现和本轮验证见[实施记录](../reviews/2026-11-19-gameplay-progression-implementation.md)，成长节奏及限制见[模拟报告](../reviews/2026-11-19-progression-simulation.md)。

## 1. 要解决的问题与目标节奏

用户真实反馈：招募弟子后，约一天打完手头内容；升级宗门主殿又缺资源，随后无事可做。后续开发同时解决持续目标、个人培养、主动玩法与阶段续接。

已确认的体验目标：

- 每天主动游玩约 30–60 分钟，包括配装、刷怪、秘境、攻宗与抵御外敌。
- 正常游玩约一周完成第一地区、获得升仙令牌并具备进入下一地区的能力。一周是玩家成长目标，不是现实时间解锁条件，也不是开发工期。
- 主要追求六名主力的个人装备；武器、盔甲、靴子、戒指合计 24 个装备位。驻守资源与守山推进为持续培养提供支撑。
- 配队研究 Boss、秘境内选路与临场取舍、数值战力不断增长，三者都属于核心乐趣。
- 挂机稳定支持个人培养；愿意主动刷怪时，可以消耗行动力加快成长。

核心循环：

> 挂机与驻守积累 → 培养六名主力、刷装配装 → 秘境探索与攻宗 → 片区守关及关键入侵 → 获得升仙令牌 → 解锁新地区图层 → 继续成长。

行动力用尽且没有待迎击内容时，仍可进入演练；持续成长收益由行动力、有限正式迎击奖励和挂机产出共同约束。

## 2. 已确认的玩法方向

| 模块 | 访谈定案 |
|---|---|
| 个人装备 | 取消普通装备的全宗加成，装备收益只属于穿戴弟子；首版围绕武器、盔甲、靴子、戒指四个部位 |
| 装备转移 | 普通装备可以卸下、转给其他弟子，同一件装备同一时间只由一人穿戴 |
| 专武 | 保留专属弟子与专属锻造途径 |
| 普通装备来源 | 刷副本、打 Boss 掉落；炼器阁承担装备提升、洗练、熔炼及专武锻造 |
| 强化 | 四个部位都可强化 |
| 随机属性 | 轻度随机，属性强度有高低档位；具体档数、结构与概率需在装备阶段定表 |
| 洗练 | 花材料重抽副属性及档位，保留主属性和强化等级；新结果产生后可选择保留旧属性 |
| 熔炼 | 多余装备可变为强化材料；资源消耗按 80% 回收的原则保留，具体核算边界见第 8 节 |
| 秘境 | 有选路、敌情与道法等局内决策；失败保留此前已经获得的装备和材料 |
| 世界地图 | 大地图模式；每个地区是一张图层，宗门各占固定位置 |
| 地区推进 | 每地区分片区；片区内自由选择宗门、副本等目标，击败守关 Boss 开放下一片区，难度递增 |
| 新旧地区 | 升仙令牌用于解锁新地区；已开放地区可切换，旧地区和原有驻守产出保留 |
| 主动加速 | 反复刷怪、刷材料与装备受行动力限制；现有论道继续承担定向补料作用 |
| 正式入侵 | 不消耗行动力，成长奖励有限，敌人逐步增强，由玩家选择接战 |
| 普通入侵 | 挂机积攒敌情，待迎击波次有上限，提供培养资源 |
| 关键入侵 | 随地图推进出现，地区最终入侵首领提供升仙令牌 |
| 演练 | 可随时进行，正式奖励领完后仍能研究阵容和挑战纪录 |

首通后的过渡仍采用已选方向：通过一段新的挑战获得关键建材，连接主殿升级和下一批内容。地图化时把它融入第一地区的推进路线，具体由哪场挑战承载在地区规则中确定。

## 3. 本轮改造前的实现基线

以下记录开工前核对到的差异，用于说明改造范围；不是本轮完成后的功能清单，也不引用旧任务通过记录作为本次验证：

| 当前实现 | 后续改造 |
|---|---|
| 属性丹写入个人 `disciple.bonuses`；普通法器仍写入 `state.bonuses` | 保留个人服药，建立普通装备的个人穿戴与收益；单独处理旧器具全局加成 |
| 专武已有专属锻造、穿戴和等级；按定义 ID 记录唯一武器 | 普通随机装备需要可区分的实例，允许同名装备有不同副属性、强化和归属；专武接入四槽规则 |
| 弟子最高三境、10 级；设施最高三级，主殿开放 3/6/9 座外宗，问道塔最多三阶 | 以地区续接成长上限，明确各地区可达到的境界、设施和装备强度 |
| 宗门入口是已有宗门的卡片选择；存档没有地区、片区、飞升进度 | 建立地区归属、固定地图位置、片区解锁及跨区状态 |
| 入侵配置为 `enabled: false`，出征接口只接受塔与远征 | 新增正式迎击、敌情积攒、关键入侵、演练及令牌使用的完整流程 |
| 塔等现有模式失败会折算待结算收益，征讨与论道另有分支 | 新秘境实现已获得装备和材料的保留；明确模式边界，保留现有规则直到另有定案 |
| 已有真实选路编成、条件道法、自动战报；节点主要仍为战斗 | 丰富局内取舍与首领机制，复用已有真实战斗和道法能力 |
| 挂机按事件切段，基础行动力恢复 0.5/h，最多补算 12h | 以新节奏重新测算恢复与消耗；跨地区驻守继续遵守同一人员和补算规则 |

直接入口：`backend/app/domain/items.py`、`craft.py`、`weapons.py`、`progression.py`、`facilities.py`、`conquest.py`、`run_engine.py`、`settle.py`、`deployment.py`，以及 `models/save.py`、`api/run.py`、`frontend/src/views/ExpeditionPanel.vue`、`config/modes/invasion.json`。

历史任务卡的状态与实际实现存在不同步处。后续开工按代码与实际产物重新核对，避免重复建设。T21 的道法深度、T22 的路线、T23 的复盘成果作为基础复用；T24 的独立视觉范围继续单独管理。

## 4. 首版规则候选

本节保留开工时用于收敛范围的设计。已落地边界见第 8 节及实施记录，后续扩展仍须单独定案。

### 4.1 六名弟子的装备目标

- 首版采用固定主属性加少量随机副属性；优先验证一条副属性、三个强度档位是否足够有趣。
- 装备部位限制合理的属性池，让不同定位有可选装备；较低档但适配的属性可以优于不适配的高档属性。
- 强化先提升主属性，洗练调整副属性，明确两类投入各自解决什么问题。
- 同名掉落可以有不同实例；实例保留来源、实际属性、强化投入和归属，换人穿戴不重抽属性。
- 锁定和熔炼预览帮助保护正在培养的装备；批量操作范围后续按真实背包负担决定。
- 专武先保留现有身份和锻造基础。是否新增改变技能的专武能力，放到代表角色验证后另定。
- 一周内先验证 24 个装备位逐步配齐、关键部位有所强化，并出现定向换装目标；全员极品不作为飞升条件。

### 4.2 地图、Boss 与秘境

- 每片区提供数个用途不同的目标：定向资源宗门、特定部位掉落、副本和守关挑战；先用少量代表内容完成闭环。
- 片区难度固定，下一片区提供更高压力和更好收益。玩家成长后重打旧目标应真实更轻松。
- 守关 Boss 通过可见技能、编成和威胁让玩家有理由调整阵容，不用总战力门槛替代实际战斗。
- 秘境用有限的强敌、补给或机缘选择建立局内取舍；节点类型、次数和效果在该阶段定表。
- 把已经获得的战利品与尚未获得的奖励分清。秘境失败时带回已经取得的装备与材料，结算后只入账一次。
- 地图浏览和切换已开放图层建议免费；移动方式、据点数量和地图美术另按最小可用方案定稿。

### 4.3 入侵与演练

- 普通敌情由服务端按经过时间补算并受存量上限约束；不得通过刷新或切图层重复积攒。
- 关键入侵按地区与片区记录触发和领取状态；重复查看、失败重试、演练不能重复领取正式首胜和令牌。
- 建议普通入侵按成功迎击进度递增，并保持所在地区的难度边界；具体公式和失败后的波次待定。
- 建议敌情保留待迎击、不设现实时间倒计时；正式失败的伤势、波次消耗和其他代价另定。
- 演练奖励为零，不消耗行动力；建议不写回永久伤势、战利品、正式入侵进度及令牌记录，使其能用于反复试阵容。
- 首次取得升仙令牌建议绑定明确里程碑。令牌数量、消耗和失败重试规则开工前定稿。

### 4.4 飞升与旧地区

- 规划假设：弟子与既有培养、装备和强化随宗门继续成长；具体地区成长表与继承细则需写入实施规则。
- 每次只解锁一个新地区，后续进入已经开放的地区不反复支付解锁令牌。
- 首版至少验证第一地区到第二地区的完整过程，第二地区要有可实际挑战的内容。
- 旧区驻守继续产出，同一弟子跨地区仍只能有一个岗位；切图层不复制驻守贡献、不冻结旧区收益。
- 新地区同步续接境界、装备强度、设施与问道塔难度，并保留旧区进度和历史事实。
- 问道塔继续承担各地区的阶段挑战；是否成为飞升硬条件需另定。

## 5. 建议开发顺序与验收

本表为依赖顺序，不承诺开发日历。各阶段仅运行受影响检查，视觉与设备体验由用户人工验收。

| 阶段 | 交付范围 | 玩家可核查结果 | 验证重点 |
|---|---|---|---|
| P0：规则与旧档方案 | 装备实例、洗练、80% 熔炼口径；地区身份与继承；行动力和一周经济预算；旧全局器具转换规则 | 能看懂如何培养一个弟子、旧投入如何保留、第一周有哪些目标 | 规则例算、隔离旧档样例、依赖和资源来源核对；阻塞问题定案后进入相关实现 |
| P1：个人配装与掉装闭环 | 四槽穿戴与转移、专武保留、可重复掉装的代表战斗、强化、洗练与熔炼，弟子详情显示真实个人收益 | 打到装备给指定弟子穿，只有该弟子变强；多余装备能支持继续培养；换装后能重新挑战代表 Boss | 装备归属、实例不重复、回收例算、CAS、旧档与出征快照；受影响前端测试和构建 |
| P2：第一地区与秘境 | 固定据点地图、片区内自由挑战、守关解锁；攻宗驻守与定向补料；有取舍的秘境；首通建材过渡 | 玩家能选想刷的目标；攻克外宗后形成稳定供给；秘境失败仍带回已获得战利品 | 地区与片区身份、解锁、掉落确定性、失败结算、岗位调度、来源配置和接口检查 |
| P3：守山循环 | 挂机敌情、关键入侵、有限正式奖励、渐强敌人、无限演练、地区最终入侵和令牌获取 | 行动力用尽后，有敌情时仍可正式迎击；无敌情时可演练；配装和配队能帮助通过更强入侵 | 时钟与积攒上限、波次状态、触发与奖励防重、零行动力接战、演练不获正式收益 |
| P4：跨区飞升与首周平衡 | 令牌解锁第二图层、成长上限续接、跨区驻守、地区问道塔、第一周节奏调校 | 能带着成长进入第二地区；旧地区可回、驻守继续；约一周的目标在多组隔离样本中有支撑 | 跨区唯一性、进度继承、令牌消耗原子性、旧区时间切段、成长与行动力预算、相关契约和构建 |

第一份可玩的交付以 P1 为界，包含实际掉装、个人穿戴和可比较的战果。第一地区的一周飞升闭环在 P4 完成后验收。

P0 至少提供两类旧档样例：拥有多个全局器具及个人丹药的存档、存在已强化专武或进行中出征的存档。转换应可重复验证，不丢失个人培养、不重复发补偿、不改写已经固化的出征输入。遇到无法从历史记录确定的全局加成，提交明确转换选择，不猜测原始归属。

## 6. 第一地区节奏草案

以下为测量目标，日期范围不触发系统锁定：

| 正常游玩阶段 | 主要活动 | 需要观察的体验 |
|---|---|---|
| 约第 1–2 天 | 配出六名主力的初步装备，攻克首批外宗，接触首个机制 Boss | 首批通关后仍有能立即追求的装备、建材与挑战 |
| 约第 3–5 天 | 定向刷关键件、强化与洗练、调整驻守，探索后续片区与普通入侵 | 挂机收取能转成个人提升；主动投入明显加快进度；路线与配队有不同选择 |
| 约第 6–7 天 | 补足弱项、迎击地区关键强敌，获得令牌，进入第二地区 | 飞升目标清楚，失败仍有积累，成功后可以实际继续玩 |

每天 30–60 分钟的候选分配：5–10 分钟收取、培养和驻守安排，15–30 分钟刷装或探索，10–20 分钟攻关、守山或验证配队。用户可按当日目标自由分配，具体耗时需人工试玩反馈。

先测产出、战斗次数和操作量，再调整行动力成本、恢复、掉落与强化消耗。当前 0.5/h 的行动力基线不直接视为新版本适用数值。已确认刷装受行动力限制，正式入侵不消耗同一份行动力。

## 7. 数值与完成证据

各期围绕六名主力、24 个装备位建立隔离样本，至少记录：

1. 挂机与各地区驻守的资源贡献、角色占岗与回岗；主动刷取带来的额外培养进度。
2. 配齐可用装备的速度、重复掉落量、各部位缺口、关键属性获取与洗练成本。
3. 强化、熔炼与换装的净消耗，低档装备和洗练投入的回收结果；反复洗练或熔炼不产生净资源增殖。
4. 每天可用行动力、实际有奖出征次数、普通敌情数量、关键入侵解锁条件及令牌取得时间。
5. 对照偏挂机与每天主动游玩 30–60 分钟的路径；主动游玩有明显加速，挂机路径持续能够培养。
6. 普通及较差掉落样本、相同成长下不同合理配队样本；首周目标不依赖某一件极品装备。
7. 相同队伍换装前后的真实战报，至少出现有理由的战果变化；旧 Boss 因成长变轻松，新 Boss 产生新压力。
8. 升级主殿并开放新内容后的实际库存和行动力，记录玩家当时还能做什么，避免再次出现只完成升级就停住的断点。

自动化证据记录种子、输入、规则版本与实际结果。点击负担、路线是否有趣、30–60 分钟是否合适以及手机表现，由用户人工试玩确认。

## 8. 首版实施边界

已确认的方向不再逐项重复询问。本轮按下表收敛首版范围：

| 决策 | 已确定 | 首版落实与后续边界 |
|---|---|---|
| 80% 熔炼 | 资源消耗存在 80% 回收原则，可转为强化材料 | 装备本体按阶数产出炼器精粹；强化及可追溯旧锻造累计投入按资源返还 80%，逐项向下取整；洗练不退，专武首版不熔炼 |
| 属性与强化 | 轻随机、属性有档位、四部位可强化 | 固定主属性、一条副属性、三个强度档位；四槽均强化主属性，实例保留投入和归属；每级炼器阁开放三级强化 |
| 旧器具 | 普通装备改成个人收益，已有培养需要保护 | 仅转换历史器具记录能解释的全局加成，无法辨识余量保留；转换幂等，先结清旧收益；专武、个人丹药和已经固化的出征输入保留 |
| 入侵 | 普通挂机积攒、关键随地图触发、正式不耗行动力、演练可无限玩 | 每 4h 积攒一波，最多待迎击三波；成功后波次递增，失败保留本波；关键入侵首胜一次；演练无永久奖励、伤势与正式进度 |
| 飞升 | 令牌来自地区最终入侵、用于新地图图层，旧地区可回且驻守保留 | 首版两地区各三片区；最终关键入侵首胜发令牌，消耗一枚开放下一区；不额外要求爬塔；回旧区不收回成长上限，塔纪录分区保存 |
| 周期与消耗 | 每天主动 30–60 分钟，首区约一周，主动刷怪耗行动力 | 秘境两点、守关一点、正式入侵零点、问道塔三点；地图策略 30/60 分钟预算分别在第 5–7/5–6 天取得令牌，各八个种子；保留 12h 补算上限。模拟时长只是操作预算，不能代替人工体验 |

洗练新候选生成后立即持久化，消耗只发生一次，刷新恢复同一候选；保留或替换不再重抽。每件装备最多保留一个待选结果，处理后才能继续洗练、强化或熔炼。

## 9. 技术、验证与范围

- 沿用 Vue 3、TypeScript、Pinia、现有主城与战报演出，以及 FastAPI、Pydantic、整档 JSON、SQLite 和 revision CAS；地图扩大不引入第二套玩法状态。
- 装备掉落、词条、洗练、节点、敌情及战斗全部由服务端既有确定性随机与状态流程计算。生成时持久化，读取和回放不重抽。
- 每件随机装备需要稳定实例身份；地区内的据点、塔进度、入侵、驻守与首胜记录需要可区分的地区身份，避免跨图层覆盖。
- 改动资源或产出前补算旧区间，再一次原子保存；跨区切换、装备变更及新设施不能吞掉离线收益。同一弟子不得跨区重复占岗。
- 保留 `run_seed`、随机游标和固定战斗快照；在局外换装、升级或切地区不改写进行中的出征。
- 消耗、领取、装备、熔炼、洗练选择和飞升使用当前 revision；请求结果不确定只查询，不自动重发。
- 模型字段从 Pydantic 导出 OpenAPI 再生成 TypeScript；不手改生成产物。按变更范围补充旧档默认或显式转换并验证导入导出。
- 首版复用现有美术与战斗能力，地图、装备图标优先本地可复现绘制。付费生图、部署与服务器变更仍按各自授权处理。
- 新玩法样本和迁移验证使用隔离存档与临时数据库，不访问或清理用户真实存档。

按各期实际改动运行相关后端、工具与前端检查。例如装备期关注 `test_items.py`、`test_weapons.py`、`test_craft.py`、`test_facilities_crafting.py`、`test_run_party_snapshot.py`、序列化与 CAS；地图与驻守关注征讨、挂机、值守和离岗回岗；秘境结算与新入侵新增对应回归。配置、随机源、接口契约、前端构建仅在受影响时检查。

本轮首版已实现并完成相关检查，实际结果集中记录在实施记录中；首轮32档成长测量及限制见模拟报告。未运行无关全量检查，未进行浏览器或视觉验收。首周节奏、配装取舍和移动端使用感受仍需人工试玩确认。
