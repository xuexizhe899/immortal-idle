# T22 实施计划

**目标：** 消除问道塔重复路线，固定候选编成与奖励，减少反复跳过战报的操作。

**架构：** 沿用 `run_engine.py` 的完整状态流。路线只增加已生成敌人列表，出发快照记录路线版本；预览和执行采用一致的敌人属性与气血取整规则。前端展示服务端输入与战报，不判断胜率或收益。

**技术栈：** 现有 FastAPI / Pydantic 与 Vue / TypeScript，不新增依赖。

## 已核对的边界

- 依据 `fb4ce4a`，T21 代码缺陷已修复，三种打法的研究结论仍缺证据，不作为本期已证明的前提。
- 正式塔仍为 20 层，仅第 20 层首领；现有战报和选路已同屏，不额外制造页面合并工作。
- 不增加恢复、整备、机缘或资源货币，不改出征人数、战斗轮数、丹药、专武与永久状态。
- 保留原每槽位普通/精英类型概率。当前类型只在当前与前一层段的编成中不放回选择；该类型没有不同编成时省略重复槽位，不为了凑两条强行增加精英出现机会。
- 编成仍按本层强度成长。货币奖励按相对当前类型层段基准的面板战力缩放，限制为 0.85–1.3；材料数量与首领奖励沿用原规则。面板战力不代表技能危险度，界面同时显示真实威胁。

## 实施与验证

1. `models/save.py` 增加 `RunNode.enemies` 默认空，`RunPartySnapshot.route_version` 默认 1，新局显式为 2。旧局整局继续旧生成与 RNG 顺序，不只兼容眼前候选。通过缺字段导入、继续推进与精确游标测试验证。
2. `run_engine.py` 在生成候选时计算固定编成、基础战力与胜利奖励，进入后读取同一节点。由测试逐层核对候选战力与实际敌人面板，不建立节点插件或策略框架。
3. 在 `config/modes/tower.json` 放奖励上下限，`tools/validate_config.py` 校验范围与有限值。其他自定义测试模式未设置缩放时维持原奖励。
4. 前端从本局快照读取敌人名称、技能、被动与总层数；旧局空编成按原层段回退。播放下拉框增加“直接看结果”，保持所有路线和道法由玩家自己选择。
5. 添加领域/API/前端回归，覆盖候选去重、真实编成、已保存奖励、配置变化、刷新、导入、CAS、防重复入账和旧局继续。导出 OpenAPI、生成 TypeScript 后执行受影响检查。
6. `tools/measure_routes.py` 使用真实内存存档跑有限的旧/新路线矩阵，记录所有资源收益、自然推进快照和命令数。两组真实状态的取舍通过同候选分支的实际战果解释，不能只靠文案或面板大小。
7. 更新 `artifacts/t22/route-and-pacing.md`、平衡报告与任务清单，真实记录例证和限制。用户人工试玩前不宣称点击时长达到 3–5 分钟，不执行浏览器视觉验收。
